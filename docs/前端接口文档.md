## 三、通用请求封装 (request.ts)

### 3.1 请求拦截器

```typescript
// 自动在请求头添加 JWT token
config.headers.Authorization = `Bearer ${token}`
```

Token 从 `localStorage` 中的 `userInfo` 对象获取：

```typescript
const { token } = JSON.parse(localStorage.getItem('userInfo'))
```

### 3.2 响应拦截器

| HTTP 状态码 | 处理逻辑 |
|------------|---------|
| 200 / 0 | 返回 `response.data`，即 `data` 字段 |
| 401 | 清除本地用户状态，跳转登录页 |
| 其他 | 弹出 Element Plus 错误提示，返回 `Promise.reject` |

### 3.3 请求方法

```typescript
// GET 请求
request.get<T>(url: string, config?: AxiosRequestConfig): Promise<T>

// POST 请求
request.post<T>(url: string, data?: any, config?: AxiosRequestConfig): Promise<T>

// PUT 请求
request.put<T>(url: string, data?: any, config?: AxiosRequestConfig): Promise<T>

// DELETE 请求
request.delete<T>(url: string, config?: AxiosRequestConfig): Promise<T>
```

**环境数据解析：**

`processNotes` 字段存储格式（环境监测）：

```
温度: 40.0°C, 湿度: 90.0%, 烟雾: 150.0ppm, 光照: 600.0lux | 阈值-温度: 35.0°C, 阈值-湿度: 80.0%, 阈值-烟雾: 100.0ppm, 阈值-光照: 500.0lux
```

前端通过正则表达式解析：

```typescript
// 解析实际值
/温度:\s*([\d.]+)/           // 温度
/湿度:\s*([\d.]+)/           // 湿度
/烟雾:\s*([\d.]+)/           // 烟雾
/光照:\s*([\d.]+)/           // 光照

// 解析阈值
/阈值-温度:\s*([\d.]+)/     // 温度阈值
/阈值-湿度:\s*([\d.]+)/     // 湿度阈值
/阈值-烟雾:\s*([\d.]+)/     // 烟雾阈值
/阈值-光照:\s*([\d.]+)/     // 光照阈值
```

## 六、事件类型与显示逻辑

在 `RecordManagement.vue` 中，根据 `cameraName` 和 `detectionResult` 字段判断事件类型：

| 事件类型 | 判断条件 | 显示内容 |
|---------|---------|---------|
| 监控异常（视频） | `cameraName` 非特定，且非环境/声音记录 | 检测图片、事件类型、检测描述 |
| 环境异常 | `cameraName === '环境监测'` 或 `aiDescription.startsWith('env_')` | 温度、湿度、烟雾、光照、阈值对比 |
| 声音异常 | `audioUrl` 非空 | 音频播放器、关键词、时长 |

## 九、补充说明（2026-04 更新）

### 9.1 实时监控新增录像能力

`monitor/index.vue` 现在新增了以下能力：

- 选择录像摄像头（`cam0 / cam1`）
- 开始录像 / 停止录像
- 查看录像文件列表
- 下载 `.mp4` 文件

对应前端请求：

```typescript
fetch('/api/rknn/record/status')
fetch('/api/rknn/record/start?cameraId=1', { method: 'POST' })
fetch('/api/rknn/record/stop?cameraId=1', { method: 'POST' })
fetch('/api/rknn/record/files?cameraId=1')
window.open('/api/rknn/record/file?name=xxx.mp4')
```

### 9.2 实时监控刷新行为

刷新按钮现在会：

- 重新拉取后端摄像头列表
- 保留默认双路 `cam0/cam1`
- 尽量恢复刷新前的显示摄像头

不会再出现“点一次刷新后只剩一个摄像头”的情况。

### 9.3 监控设备显示规则

- 默认双路占位设备，如果没有真实位置配置，列表中会优先展示 `RTSP` 地址
- 如果后端把 `camera.name` 直接填成 `rtsp://...`，前端会自动回退成可读名称，例如 `摄像头1 (cam0)`
