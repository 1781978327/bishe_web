# yolov8-rk3588-cpp-3-15 运行说明

## 1. 编译

推荐直接在项目根目录使用现有 `build/` 或 `build_release/`：

```bash
cd /home/orangepi/Desktop/web/bishebeifen-master/yolov8-rk3588-cpp-3-15/build
cmake ..
make -j2 rknn_http_ctrl rknn_yolov8_demo
```

如果你更偏向发布构建：

```bash
cd /home/orangepi/Desktop/web/bishebeifen-master/yolov8-rk3588-cpp-3-15
mkdir -p build_release
cd build_release
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j2 rknn_http_ctrl rknn_yolov8_demo
```

## 2. 启动流媒体服务

当前推荐直接从 `build_release` 目录启动 `rknn_http_ctrl`，让它自动拉起 `mediamtx`。

这样会同时开放：

- RTSP: `8554`
- WebRTC(WHEP): `8889`
- ICE: `8189/udp`

如果你想手动启动 `mediamtx`，也可以：

例如：

```bash
./mediamtx
```

确认 `8554` 已监听：

```bash
ss -ltn | grep 8554
```

如果要确认 WebRTC：

```bash
ss -ltnup | grep -E '8889|8189'
```

## 3. 启动 HTTP/RTSP 服务

```bash
cd /home/orangepi/Desktop/web/bishebeifen-master/yolov8-rk3588-cpp-3-15/build_release
sudo ./rknn_http_ctrl --cam0-source /dev/video0 --cam1-source /dev/video2
```

默认端口：

- HTTP: `8091`
- RTSP: `8554`
- WebRTC(WHEP): `8889`

默认摄像头：

- `cam0 -> /dev/video0`
- `cam1 -> /dev/video2`

如果报错：

- `Device '/dev/video0' is busy`
- `Device '/dev/video2' is busy`
- `bind 端口 8091 失败`

通常是旧进程未退出，先清理：

```bash
printf 'orangepi\n' | sudo -S pkill -x rknn_http_ctrl || true
printf 'orangepi\n' | sudo -S pkill -x mediamtx || true
printf 'orangepi\n' | sudo -S fuser -v /dev/video0 /dev/video2 || true
ss -ltnp | grep -E '8091|8554|8889' || true
```

## 4. 快速测试摄像头 RTSP

先准备：

```bash
BASE=http://127.0.0.1:8091
```

启动摄像头裸流：

```bash
curl -X POST $BASE/api/video/stop
curl -X POST $BASE/api/rtsp/start
```

本机探测：

```bash
ffprobe -v error -rtsp_transport tcp \
  -show_entries stream=codec_name,width,height,avg_frame_rate \
  -of json rtsp://127.0.0.1:8554/cam0

ffprobe -v error -rtsp_transport tcp \
  -show_entries stream=codec_name,width,height,avg_frame_rate \
  -of json rtsp://127.0.0.1:8554/cam1
```

当前回归结果：

- `cam0`: `h264 640x480 @ 30fps`
- `cam1`: `h264 640x480 @ 30fps`

WebRTC/WHEP 地址：

- `http://127.0.0.1:8889/cam0/whep`
- `http://127.0.0.1:8889/cam1/whep`

如果前端在同一局域网下访问本机，建议前端根据当前页面主机动态生成 WHEP 地址，不要长期在 `.env.local` 写死旧 IP。

## 5. 快速测试视频 RTSP

视频模式现在走的是：

- `FFmpeg RKMPP` 解码视频
- 优先输出 `DRM_PRIME`
- 从 `AVDRMFrameDescriptor` 提取 `dma-buf fd`
- `RGA -> RKNN input_mem`
- 若 `DRM_PRIME` 不可用，仍保留 `NV12/OpenCV` 回退路径

### 5.1 只推视频裸流，不开推理

```bash
curl -X POST $BASE/api/rtsp/stop
curl -X POST "$BASE/api/inference/off?unload=1"
curl -X POST $BASE/api/video/stop

curl -X POST $BASE/api/video/start \
  -H 'Content-Type: application/json' \
  -d '{"path":"/home/orangepi/Desktop/web/bishebeifen-master/yolov8-rk3588-cpp-3-15/video/person.mp4","loop":true}'

curl -X POST $BASE/api/rtsp/video/start
```

本机探测：

```bash
ffprobe -v error -rtsp_transport tcp \
  -show_entries stream=codec_name,width,height,avg_frame_rate \
  -of json rtsp://127.0.0.1:8554/cam3

ffmpeg -v error -rtsp_transport tcp \
  -i rtsp://127.0.0.1:8554/cam3 -t 3 -f null -
```

当前回归结果：

- `cam3`: `h264 1920x1080 @ 25fps`
- 不开推理时，本机 `ffprobe` / `ffmpeg` 也能直接拉流

### 5.2 视频推理 + RTSP

```bash
curl -X POST $BASE/api/video/start \
  -H 'Content-Type: application/json' \
  -d '{"path":"/home/orangepi/Desktop/web/bishebeifen-master/yolov8-rk3588-cpp-3-15/video/person.mp4","loop":true}'

curl -X POST "$BASE/api/inference/on?track=0&model=/home/orangepi/Desktop/web/bishebeifen-master/yolov8-rk3588-cpp-3-15/model/RK3588/yolov8s.rknn"
curl -X POST $BASE/api/rtsp/video/start
```

如果链路切到 `DRM_PRIME` 成功，服务端日志里会出现类似：

```text
[Video] FFmpeg DRM_PRIME 已打开: 1920x1080 @ 25.0 fps
[VideoDecode] frame_fmt=drm_prime(179) drm_valid=1 nv12_valid=0
```

## 8. 已知说明

- `cam3` 启动后立刻探测时，首次偶发 `404`，通常等待约 `1` 秒后重试即可
- 视频 RTSP 当前仍可能出现 `non monotonically increasing dts` 警告，但不影响本机 `ffprobe` / `ffmpeg` 拉流
- `Ctrl+C` 退出时，当前版本已修复 `DRM_PRIME` 视频模式下的常见段错误，正常情况下会打印“模型资源已清理 / 服务已退出”
- 若切换模型、标签或跟踪算法，建议先执行：

```bash
curl -X POST "$BASE/api/inference/off?unload=1"
```
